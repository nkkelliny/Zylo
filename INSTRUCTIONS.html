1. Overview

Zylo is a desktop web browser built using Electron, with:

  • A main Electron process (main.js) for windows, downloads, and permissions.
  • A renderer UI (renderer.js + index.html) for tabs, panels, downloads shelf, and AI chat.
  • A local Express backend (server.js) for profiles, bookmarks, history, downloads, settings, permissions, and AI proxy.
  • A preload script (preload.cjs) bridging secure IPC between renderer and main.
Data Storage: Profiles, bookmarks, history, downloads, permissions, and settings are stored in a local JSON/DB file managed by db.js. Each profile is separate and can have its own browsing data.

2. Requirements

  • Node.js (LTS recommended) and npm.
  • Git (for cloning the repo, if applicable).
  • Electron and dependencies (installed via npm install).
  • Ollama installed and running locally on http://localhost:11434 if you want Zylo AI.

3. Install & Run

  1. Clone or download the project (if from Git):
    git clone <your-zylo-repo-url>
  2. Change into the directory:
    cd zylo
  3. Install dependencies:
    npm install
  4. Start the Express backend (dev):
    node src/server.js
    In packaged mode the backend is imported automatically by main.js.
  5. Start Electron:
    npm run start (or your configured start script).
Note: For development, ensure server.js is running so the renderer can reach http://localhost:3001. In packaged builds, startBackendIfPackaged() imports server.js automatically.

4. UI Tour

4.1 Top Toolbar

The toolbar contains navigation controls, address bar, profile selector, zoom controls, dev tools, AI, and menu.

  • Back / Forward: Navigate through history of the active tab.
  • Reload / Stop: Reload the current page or stop loading.
  • Address Bar:
    • Enter a full URL (https://example.com) or a search term.
    • If there is no protocol and it looks like a search, Zylo uses the configured search engine.
  • Lock Icon: Shows 🔒 for HTTPS, ⚠ for non-HTTPS, ⚪ if unknown.
  • Profile Selector: Switch between profiles.
  • Zoom Controls: -, 100%, +.
  • DevTools: Opens Chromium DevTools for debugging.
  • New Window: Opens another Zylo window.
  • AI Button: Opens the AI panel for Zylo AI.
  • Menu Button: Shows/hides the left side panel.

4.2 Tabs Strip

  • Tabs are created dynamically by renderer.js.
  • Each tab shows an icon (favicon if available, otherwise 🌐) and the page title.
  • Use the + button or keyboard shortcut to open new tabs.
  • Close a tab via the × button or keyboard shortcut.

4.3 Side Panel

Side panel contains multiple tabs:

  • Bookmarks
  • History
  • Downloads
  • Permissions
  • Settings
  • Sync
  • AI

4.4 Downloads Shelf

At the bottom of the window, a Downloads Shelf shows active and recent downloads as chips with progress bars. You can hide the shelf using the "Hide" button.

5. Profiles

Profiles are managed via the backend (/api/profiles) and are selected with the profile dropdown in the toolbar. Each profile has its own settings, bookmarks, history, downloads, and permissions.

5.1 Switching Profiles

  1. Click the profile dropdown in the toolbar.
  2. Select a different profile.
  3. The renderer calls /api/profiles/activate and then window.native.switchProfile(id).
  4. A new window is created for that profile and the old window is closed.

5.2 Creating Profiles

New profiles can be created via the API or UI (if you have a profile creation UI wired to /api/profiles). New profiles copy the settings of the currently active one, but start with empty bookmarks/history/downloads/permissions.

6. Navigation & Tabs

6.1 Loading Pages

  1. Click on the address bar.
  2. Type a URL (e.g., https://example.com) or a search term.
  3. Press Enter.
  4. Zylo will:
    • Use the configured search engine if it detects a search term.
    • Prepend https:// if it looks like a domain.

6.2 Tabs

  • New tab: Click + or use the keyboard shortcut.
  • Close tab: Click × on the tab or use the shortcut.
  • Switch tab: Click on a tab; active tab is highlighted.

6.3 Find in Page

  1. Click the "Find in page" button in the toolbar.
  2. Type search text.
  3. Use ↑ / ↓ buttons to navigate matches.
  4. Close the find bar with the ✕ button.

7. Bookmarks & History

7.1 Bookmarks

  • Open the side panel > Bookmarks.
  • Click "Add current tab" to bookmark the active page.
  • Bookmarks store title, URL, favicon, and timestamp.
  • Click a bookmark to open it, or "Delete" to remove it.
  • Keyboard shortcut: Ctrl/Cmd + D to bookmark the current page.

7.2 History

  • Open the side panel > History.
  • History shows a timestamp, title, URL, and favicon.
  • Click an entry to re-open it.
  • Click "Clear All" to remove the history for the active profile.

8. Downloads

Downloads are handled by Electron’s will-download event and recorded per profile in profile.downloads.

8.1 Starting a Download

  • From any page, click a download link (file, image, etc.).
  • The main process fires will-download and sends:
    • download-started (with id, fileName, url, totalBytes)
    • Then download-updated for progress
    • Finally download-done when finished/cancelled/failed

8.2 Downloads Shelf (Live)

  • At the bottom of the window, the shelf shows active downloads as chips.
  • Each chip has:
    • File name
    • Status (percentage, done, cancelled, failed)
    • Progress bar
  • Click "Hide" to temporarily hide the shelf (downloads continue).

8.3 Downloads Panel (History)

  • Open side panel > Downloads.
  • Shows completed downloads from /api/downloads:
    • File name
    • State
    • Size
    • File path
    • Original URL
    • Timestamp

9. Permissions (Camera / Microphone / Geolocation / Notifications)

Zylo intercepts permission requests from web content in main.js using ses.setPermissionRequestHandler. It respects stored decisions per origin and presents a modal when a decision is needed.

9.1 How Permission Decisions Work

  1. Site calls navigator.geolocation.getCurrentPosition, getUserMedia, or Notification.requestPermission.
  2. Main process inspects permission and details.mediaTypes (for camera/mic).
  3. Zylo checks the active profile’s stored permissions for that origin:
    • If allow/deny is stored, it uses that automatically.
    • If ask, it sends a perm-request event to the renderer.
  4. The renderer shows a Permissions Modal with “Allow” / “Deny” options and a “Remember this choice” checkbox.
  5. Once the user chooses:
    • Renderer sends perm-respond with decision.
    • Main process persists the decision and calls callback(true/false).

9.2 Permissions Panel

  • Open side panel > Permissions.
  • Shows:
    • Current site origin and dropdowns for:
      • Camera
      • Microphone
      • Geolocation
      • Notifications
    • Buttons:
      • Save for this site – writes decisions via /api/permissions/set.
      • Reset this site – sets all to ask.
      • Reset all – clears all decisions for the profile.
    • Saved origins list – read-only summary of stored decisions.

10. Settings

  • Open side panel > Settings.
  • Options:
    • Search engine – base URL used for search queries.
    • Home page – default URL for the home button.
    • User agent – choose default or a specific UA string.
    • Adblock toggle – enable minimal ad/tracker blocking (via adblock.txt rules).
    • AI enabled – turn Zylo AI on/off.
    • AI model – default model name (e.g., llama3.1:8b).
  • Click Save to persist settings and apply user-agent change.

11. Sync (Export/Import Profile)

  • Open side panel > Sync.
  • Export JSON: Downloads a JSON export of the current profile data (bookmarks, history, downloads, settings, permissions).
  • Import JSON: Choose a JSON file and click Import to load it as a new profile (depending on your backend logic).

12. Zylo AI (Ollama)

  • Open side panel > AI.
  • Select a model from the dropdown (fetched from /api/ai/models).
  • Toggle “Enable” to turn AI on.
  • Click Save to persist AI settings.
  • In the chat area:
    • Type a question and click Send.
    • Click Ask about page to send the current page’s text to Zylo AI for summarization.
  • Backend proxies chat to Ollama at http://localhost:11434/api/chat.
If AI doesn’t respond: Make sure Ollama is installed, running, and that the model (e.g. llama3.1:8b) is downloaded and available.

14. Troubleshooting (Common Issues & Fixes)

14.1 App Doesn’t Start / Window Doesn’t Open

  • Check Node/Electron version: Use a recent LTS version of Node.js.
  • Check console output:
    • Run npm start from a terminal and look for errors.
    • Common issues:
      • Missing dependencies – run npm install again.
      • Port 3001 already in use – another process may be using it.
  • Backend not starting in packaged mode:
    • Make sure startBackendIfPackaged() in main.js is correctly importing ./server.js.

14.2 Blank Window / White Screen

  • Check DevTools: Press Ctrl/Cmd + Shift + I or click the DevTools icon to view console errors.
  • Backend not reachable:
    • Open DevTools > Console, look for failed http://localhost:3001 requests.
    • Ensure server.js is running (in dev) or started (in packaged).
  • Path issues in packaged app: Ensure index.html and assets paths are correct.

14.3 Address Bar or Inputs Don’t Accept Keyboard Input

Sometimes focus can get “stuck” in Electron or Chromium, especially after DevTools usage or window focus changes.

  • Try these steps:
    1. Click directly into the input field (e.g., URL bar) and try typing again.
    2. Minimize the Zylo window and restore it. This often forces the OS to refresh focus and fixes keyboard input issues.
    3. Switch to another app, then back to Zylo.
    4. Close and re-open the side panel if it’s covering part of the window.
    5. If that fails, close and reopen Zylo.
  • DevTools active: If DevTools is focused, keyboard input may go there instead of the page:
    • Click back on the page or the address bar.
    • Close DevTools if you don’t need it.

14.4 Pages Won’t Load / No Internet

  • Check your system network:
    • Open any external browser (Chrome, Safari, Edge) and see if websites load.
  • Check URL:
    • Make sure you’re using a valid URL (e.g., https://example.com).
    • If you entered an IP or local hostname, ensure your network can reach it.
  • Adblock interference:
    • If some scripts/resources are blocked, disable adblock in Settings and try again.

14.5 Side Panel Doesn’t Open / Nothing Shows in Panels

  • Click the Menu button: Ensure the side panel is not hidden.
  • No data:
    • If bookmarks/history/downloads are empty, it may simply be because you haven’t visited or downloaded anything yet.
  • Backend not reachable:
    • If /api/bookmarks or /api/history calls fail, make sure server.js is running.

14.6 Downloads Don’t Start / No Chips on Shelf

  • Check DevTools Console:
    • See if any errors appear when clicking a download link.
  • Check context menu:
    • Right-click an image or link and choose “Save Image As…” or “Open link in new tab” then try download.
  • Ensure will-download is firing:
    • In main.js, verify that the ses.on('will-download') handler is wired for the session you’re using.
  • Check file permissions:
    • If your OS blocks access to the default download folder, choose a different directory (OS dialog).

14.7 Downloads Missing from Downloads Panel

  • Check that downloads are being persisted:
    • After a download finishes, main.js writes to profile.downloads via db.js.
  • Refresh the Downloads panel:
    • Click away to another panel (e.g., Bookmarks) and back to Downloads to trigger refreshDownloads().
  • Profile mismatch:
    • Make sure you’re looking at the same profile that initiated the downloads.

14.8 Permissions Modal Doesn’t Show

  • It might have an existing decision:
    • If a decision for that origin and permission was already saved, Zylo will auto-allow/deny and not show UI.
    • Open Permissions panel and reset the site or all sites.
  • Check IPC wiring:
    • Ensure onPermissionRequest is correctly wired in preload.cjs and renderer.js.
  • Check origin:
    • If the origin is about:blank or invalid, it may be rejected by your logic.

14.9 Permissions Always Denied / Camera/Mic Not Working

  • Reset permissions:
    • Open Permissions panel > “Reset this site” or “Reset all”.
  • Check OS-level settings:
    • On macOS or Windows, check Privacy & Security settings to ensure camera/mic access is allowed for the app.
  • HTTPS only:
    • Some APIs (like geolocation) may require secure origins; ensure using https:// when applicable.

14.10 AI Not Working / “AI unavailable. Is Ollama running?”

  • Check Ollama:
    • Run ollama list in a terminal – ensure your model (e.g., llama3.1:8b) is installed.
    • Make sure the Ollama daemon is running.
  • Check backend:
    • Backend calls http://localhost:11434/api/chat. If port differs, update server.js.
  • AI disabled in settings:
    • Open Settings > ensure “Enable Zylo AI” is checked, and a valid model name is set.

14.11 Profile Corruption / Strange Data

  • Export profile:
    • Use Sync > Export JSON to back up the current profile.
  • Create a new profile:
    • Create a fresh profile to see if issues reproduce.
  • Inspect database file:
    • If comfortable, open your DB/JSON file and check for malformed entries.

14.12 Adblock Breaking Sites

  • Disable adblock in Settings:
    • If a site behaves strangely or key scripts don’t load, try disabling adblock and reloading.
  • Edit adblock rules:
    • Remove or adjust entries in adblock.txt that are too broad or blocking critical resources.

14.13 General “Something Feels Off” Steps

  1. Minimize & restore the Zylo window (especially when keyboard input acts weird).
  2. Close DevTools if you don’t need it and re-focus the main page.
  3. Toggle the side panel off and on again.
  4. Close and re-open Zylo.
  5. Try another profile to check if the issue is profile-specific.
Still stuck? Open DevTools > Console, capture the error messages, and investigate or share them when asking for help. The logs will usually point to server.js, main.js, or renderer.js as the source.
